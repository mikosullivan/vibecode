# Vibecode efficiency experiment


## Question

Is vibecode JSON measurably more efficient for an AI agent to consume than equivalent English prose? "Efficient" = fewer tokens.

## Method

The setup: give the same information to two cold AI agents in two different formats. One agent reads prose. The other reads vibecode. Both answer the same questions. Compare their token use at equal answer correctness.

"Cold" means each agent starts a fresh conversation with no prior context. Agents run in parallel.

### The agent

Both agents are Anthropic's Claude Opus 4.7 (`claude-opus-4-7`), the current Opus generation. Using the same model on both sides means differences in outcome are attributable to format, not to model capability. The same model also produced the vibecode version of the source material in the first place.

### Two-format comparison

The premise: the same information, encoded two different ways, should let an agent answer the same questions. If one format lets the agent reach the same answers with fewer tokens, that format is measurably more efficient.

The test uses the Wikipedia article on Shakespeare's *A Midsummer Night's Dream* as its source. Author's note: I am an avid Shakespeare enthusiast, so I chose a subject that I am familiar with.

- **Prose** — the Wikipedia article as plain text. What an agent typically finds in the wild.
- **Vibecode** — the same content translated into structured JSON. Structure explicit in fields; natural-language extraction done at authoring time by the author (Claude, in this case), so the reader doesn't have to redo it.

Both files cover identical scope — characters, plot by act and scene, sources, dating, themes, critical history, performance history, adaptations.

- [midsummer.txt](./midsummer/midsummer.txt) — 75 KB of prose, pulled as plain text via the Wikipedia API.
- [midsummer.json](./midsummer/midsummer.json) — 34 KB of vibecode (45% the size on disk) covering the same content. Generated by Claude from the Wikipedia source.

### Procedure

For each question in the list below:

1. Spawn two fresh agents in parallel.
2. Agent A gets the prose file plus the question. Agent B gets the vibecode file plus the same question.
3. Each agent reads its file and produces an answer independently.
4. Record for each: tokens consumed (input + output) and the answer.

### What we measure

- **Token consumption** — the efficiency metric. Input tokens (mostly the source file itself) plus output tokens (the answer).
- **Answer correctness** — did each agent produce a correct answer? Checked against the source.

Answer correctness has to hold at parity before token savings mean anything. If vibecode costs half the tokens but produces worse answers, the compression is lossy at the depth we care about.

### Training contamination

*A Midsummer Night's Dream* is in every large model's training corpus, and some questions may be answerable from training memory alone. Questions are designed to probe specific facts that reward reading the source over recalling it — exact character trades, precise year-venue pairings, specific director-and-year combinations. Where a question can plausibly be answered from memory, that possibility is flagged in the analysis.
